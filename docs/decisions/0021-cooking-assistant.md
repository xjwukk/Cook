# 0021 料理助手：本地粗筛 + 模型挑选

- 状态：已采纳
- 日期：2026-11-13
- 关联：[0007 AI 与整句识别](./0007-ai-and-sentence-input)、[0019 Web 视觉方向](./0019-warm-editorial-web-visual-direction)、[自托管部署](../dev/self-hosting)

## 背景

「发现」tab 之前只有一个「今天吃什么」入口。用户希望把它换成对话式的料理助手：后台配好大模型后，可以用自然语言提问，助手结合本地菜谱和自己的食材厨具回答。

两个硬约束：

1. **菜谱全在浏览器本地**（887 道菜镜像在 IndexedDB），服务端没有菜谱库。
2. 若把整份目录发给模型，每轮 20–25k tokens，且模型会编造不存在或做不成的菜——这与 0007「AI 只负责听懂，结果由现有逻辑产生」的原则冲突。

## 方案对比

| 方案                                       | 取舍                                                            |
| ------------------------------------------ | --------------------------------------------------------------- |
| 纯本地模板回答                             | 零成本、零幻觉，但不是对话，只能套固定句式                      |
| 模型面对整份菜谱目录                       | 最灵活，但每轮 20–25k tokens 且会编菜谱                         |
| **本地粗筛 → 宽候选池 → 模型挑选**（采纳） | 模型真正参与挑选与排序，候选仍是本地真实菜谱；约 1.5k tokens/轮 |
| 本地检索 + 模型只写措辞                    | 成本最低，但模型无法改变推荐结果，等于换皮模板                  |

## 决定

- **数据流**：`parseCookQuery` 解析问题 → 合并「我的厨房」与当前已选食材 → `createRecipeRecommender` 粗筛出 40–60 道真实候选 → 连同库存、收藏与历史菜名发给模型 → 模型返回挑选顺序、理由、回答段落与追问建议。
- **模型的能力边界**：只能在候选池里挑菜、排序、给理由；可以说明「还缺什么」；不能编造菜谱、用料、步骤、用量，不做营养/医疗/价格建议，不做第二轮扩检。
- **双重校验**：服务端与客户端都校验返回的菜谱 id，候选之外一律丢弃；模型没挑或全被丢弃时，回退到本地排序前 3 道。
- **登录要求**：全部功能需要登录。未登录时页面禁用输入并提示登录。
- **未配置模型**：`/api/assistant/status` 返回 `enabled: false`，页面提示并禁用输入，不做本地降级。
- **发送的数据**：食材、厨具、调料、收藏菜名、最近做过的菜名、候选菜谱（仅白名单字段）。不发送私人菜谱正文、忌口记录或账号资料。
- **配额**：按账号记每日与每分钟次数，存在 SQLite 的 `ai_usage` 表里，进程重启不会重置。
- **技术实现**：服务端 `server/src/assistant.mjs` 走 OpenAI 兼容的 `/chat/completions`，`response_format: json_object`，超时/重定向/凭据都做限制。
- **配置入口**：模型地址、模型名与 API Key 由每个账号在「我的 → 助手设置」（`/assistant-settings`）里填写，账号配置优先；服务端 `COOK_AI_*` 环境变量作为默认与兜底。Key 用 AES-256-GCM 加密存入 `ai_config` 表，接口只回显 `sk-…abcd` 提示、不回传明文；保存前可「测试连接」，也可清除配置回落默认。
- **自定义地址与模型发现**：地址既接受 base URL，也接受完整的 `…/chat/completions`，服务端统一归一化为 base；填好地址与 Key 后可请求 `{base}/models` 拉取模型列表供选择（服务端代理，避免浏览器跨域与 Key 暴露），服务商不提供该接口时提示手动填写。

## 影响

- 新增环境变量 `COOK_AI_*`；未配置时助手页不可用但站点其余功能不受影响。
- 「发现」tab 改名为「料理助手」，`/apps` 保留为别名，旧链接仍可用。
- 删除「今天吃什么」页面、`RandomRecipe` 组件与 `useRandomRecipe`；`randomPool` 仍留在 store 内部供其他逻辑使用。
- 删除了 `scripts/generate-ai-intent-contract.mjs`——它唯一的消费者（云函数）已移除，本方案也不需要词表契约。
- 新增分析事件 `ask_assistant`、`view_assistant_answer`、`click_assistant_recipe`，均不含问题原文。
- 模型服务商会收到用户主动输入的文本与上述个人数据；部署方需要在隐私说明中告知。
