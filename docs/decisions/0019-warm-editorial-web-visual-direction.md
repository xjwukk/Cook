# 0019 Web 视觉方向：温暖编辑式

- 状态：已采纳
- 日期：2026-11-11
- 关联：[0016](./0016-native-android-and-capacitor-retirement)、[设计系统与契约](../dev/design-system.md)

## 背景

Web 端此前使用 Ionic 默认主题（`--ion-color-primary: #0066cc`）配白底灰卡片，是典型的通用蓝模板观感：主色单一、卡片套卡片、字重与字号缺少对比，和「用手边食材找家常菜」这个产品的温度感不匹配。首页信息架构本身可用，问题集中在视觉层——配色、层次、排版尺度、组件质感。

同时存在三项约束：Ionic 组件主题变量驱动着已选食材芯片等核心交互状态；原生 iOS App（云食册）只与 Web 共享 `packages/data` 数据与 `packages/shared` 图标资产，样式各自独立；中文 CJK 字形不能靠外链字体解决——中文衬线 webfont 体积不可接受，不能为视觉 flourish 新增运行时依赖。

## 方案对比

| 方案                 | 取舍                                                                                                                     |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 温暖编辑式（采纳）   | 暖白纸感底 + 陶土橙主色 + 墨绿/姜黄辅色，衬线只用于拉丁与数字。贴合家常做饭的温度，零新增依赖，与 emoji 食材图标天然契合 |
| 清新现代             | 纯白 + 青绿，比现状轻盈，但与同类食谱产品区分度有限，编辑感弱                                                            |
| 沉浸厨房（暗色优先） | 近黑底 + 暖光橙，辨识度高；与筛选区密集列表和浅色内容编辑场景冲突，阅读疲劳风险大                                        |
| 保留蓝只重构层次     | 改动最小、见效最快，但保留了单色系问题，视觉辨识度提升有限                                                               |

## 决定

- Web 视觉方向定为温暖编辑式。调色板落地为四维语义色：陶土橙 `--c-brand`（主操作与已选态）、墨绿 `--c-herb`（健康与成功）、姜黄 `--c-saffron`（强调）、琥珀 `--c-warn`（缺食材等提示）；正文用墨色 `--c-ink`，分区靠 `--c-rule` 细线而非卡片描边。
- 主色取 `#B84E27`（暗色 `#E08A5F`）：比最初试用的 `#C4552D` 略深，使填充与文字两种用法都达到 WCAG AA。Ionic 的 `--ion-color-primary` 同时用于填充与文字，因此映射到更深的 `--c-brand-ink`，填充则显式用 `--c-brand`。
- 主题令牌集中在 `apps/web/app/styles/css-vars.scss` 作为唯一来源，`apps/web/app/styles/ionic.css` 只做 Ionic 变量到自有令牌的映射，组件不再直接写死颜色值。
- 排版上拉开字号与字重对比；衬线字体仅作用于拉丁字母与数字（计数、序号、字标），中文保持系统黑体栈，避免引入中文 serif webfont。
- 食材图标保留 emoji，不绘制新素材（避免影响原生端共享资产与跨端一致性），改为统一圆形容器与暖色底来消除渲染杂乱。
- 本轮范围限定为设计令牌与基础组件，布局节奏与信息层级的调整留待后续。
- 明暗双主题同时给出暖色系取值：暗色不是浅色的简单反相，而是偏暖的「夜厨房」配色，保证墨线与纸面仍有层次差。

## 影响

- 所有 `--ion-color-primary` 消费方（已选食材芯片、焦点环、主按钮）自动跟随新主色，Web 与原生 iOS 的主色一致性需要在验收时单独核对。
- 暗色模式下原先以 `--ion-background-color-step-*` 表达的分组列表底色需要覆写为暖色阶，否则会残留冷灰。
- 涉及颜色的改动必须走令牌，不允许在组件内写十六进制色值，否则会破坏明暗双主题与后续微调能力。
- `--cook-orange` 语义与新的主色冲突（原本表示「缺食材」提示），需改为独立的琥珀语义 `--c-warn`。
- 验收需要在 390×844 与 1440×900 两个视口分别截图，并覆盖加载、空、错误、部分、成功、权限六种内容状态，产出 evidence 记录并通过随 skill 附带的 `check-evidence.js`。
