# 0027 官方菜谱步骤在线编辑

- 状态：已采纳
- 日期：2026-11-27
- 关联：[0023 官方菜谱覆盖层](./0023-recipe-overrides)、[0026 用户投稿发布](./0026-user-published-recipes)

## 背景

官方菜谱的步骤正文来自 `recipe-text.json`（HowToCook，带指纹校验），`recipe.csv` 只有 9 列，没有步骤。之前管理员只能改菜名、食材、厨具等字段，写错步骤必须改数据源再重新构建。投稿发布的菜谱已经有 `note` 字段承载步骤，详情页也优先渲染 `note`；差别只是官方菜谱的编辑器没开放。

## 方案对比

| 方案                         | 取舍                                             |
| ---------------------------- | ------------------------------------------------ |
| 直接改 `recipe-text.json`    | 需要重新构建，且改动会让审核指纹失效             |
| 新增步骤表 / 结构化步骤编辑  | 需要迁移、审核和格式设计，对个人站点过重         |
| **复用 note 覆盖层**（采纳） | 无需改数据结构，立即生效；代价是步骤降级为纯文本 |

## 决定

- 官方菜谱编辑器读取 `recipe-text.json` 的「操作 / 步骤」段作为只读预览；点「编辑步骤」才进入文本框，预填转换后的纯文本。
- 保存时只在 `note` 内容与官方步骤不同时写入 `note`；内容为空或与官方相同则不写，详情页回退到 `recipe-text.json`。
- 清空步骤或点「恢复官方步骤」即删除 `note`；撤销整条覆盖也会恢复官方步骤。
- 不改 `recipe-text.json`、不改 CSV、不改服务端白名单；非投稿菜谱的覆盖行仍受 8 KB 上限，客户端在保存前按序列化字节校验。
- 补丁 CSV 没有 `note` 列，导出前提示步骤改动只保存在覆盖层。

## 影响

- 步骤被覆盖后变成纯文本，原有的有序列表、外链和加粗会降级；需要保留格式时应回到 `recipe-text.json`。
- 8 KB 覆盖行上限约合 2,600 个中文字符；超长时编辑器就地报错，不发请求。
- 详情页已经优先 `note`，无需额外渲染分支；`note` 清空后按 `recipe-text.json` 回退。
- 审核数据（食谱正文指纹、饮食目标等）不受影响，因为只改运行时覆盖层。
