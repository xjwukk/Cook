# 设计系统与契约 — 料理手帐

视觉方向见 [0019](../decisions/0019-warm-editorial-web-visual-direction.md)，品牌与 logo 见 [0020](../decisions/0020-brand-rename-and-warm-editorial-tokens.md)。本文是可检查的契约：约束、设计令牌规范、组件规范、内容状态矩阵与验收方式。

## 产品界面与用户任务

| 项       | 内容                                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------------------ |
| 产品界面 | 料理手帐 Web（Nuxt 4 + Ionic Vue + UnoCSS），主站 `cook.yunyoujun.cn`，中文界面                                    |
| 用户     | 手边食材有限的家庭做饭者，手机为主，平板与桌面为辅                                                                 |
| 核心任务 | 打开冰箱 → 勾选手边的食材/厨具 → 看到「能做哪些菜」→ 点开做法                                                      |
| 主操作   | 选食材并得到可做的菜（首页 `/home`）                                                                               |
| 次操作   | 浏览菜谱库、搜索、按厨具/做法/难度筛选                                                                             |
| 信息层级 | ① 我的食材（输入与已选）→ ② 能做的菜（结果数与结果列表）→ ③ 进一步筛选（厨具/做法/难度，可折叠）                   |
| 品牌资产 | 仓库根目录 `logo.png` 的手账插画（暖纸面 + 粉色书脊 + 薄荷绿），由 `scripts/generate-brand-icons.mjs` 派生各端尺寸 |

## 设计方向

1. **目的**：让用户三秒内知道「我家这些菜能做什么」，并把注意力留在食材与结果之间，而不是界面装饰。
2. **受众**：重复使用的家庭做饭者，扫读优先；已选食材和结果条目必须一眼可辨。
3. **调性**：温暖编辑式。暖白纸感底、墨色正文、陶土橙主操作，靠细墨线与留白分区，不用卡片描边堆叠。
4. **记忆点**：**一本摊开的食谱册**。纸张暖白底 + 陶土橙的「印章」式已选态 + 霞鹜文楷数字计数 + 食材 emoji 装在统一圆形纸章容器里。
5. **约束**：Nuxt 4 CSR / Ionic 组件 / UnoCSS(Wind3+attributify) / SCSS 令牌；字体资源站点自托管，不新增运行时 npm 依赖；明暗双主题；Web 与原生端共用品牌色与图标，但原生端保留各自平台惯例。

## 目标视口与三端断点

| 代号    | 尺寸     | 形态                                     | 断点       |
| ------- | -------- | ---------------------------------------- | ---------- |
| mobile  | 390×844  | 单列 + 底部标签栏 + 结果底部弹层         | < 768px    |
| tablet  | 834×1024 | 64px 图标导航栏 + 筛选区与结果栏两栏     | 768–1199px |
| desktop | 1440×900 | 208px 完整侧栏 + 中间筛选区 + 右侧结果栏 | ≥ 1200px   |

断点只有这三个值。新增响应式规则必须落在 `768px` / `1200px` 上，不要再用 1024 或 1280 的一次性值；移动端 `desktop` 判定（结果面板是否停靠）也以 `min-width: 768px` 为准。

## 令牌规范

令牌唯一来源为 `apps/web/app/styles/css-vars.scss`；`ionic.css` 只做 Ionic 变量到自有令牌的映射。组件内不得写死颜色值。

### 主色的两种用法

Ionic 把 `--ion-color-primary` 同时用于填充与文字。因此：

- **作为文字**（链接、选中标签、图标、`--color-selected`）：`--ion-color-primary` 映射到 `--c-brand-ink`（`#9A3F1E`，对纸面 6.34:1）。
- **作为填充**（印章态、主按钮底）：显式写 `var(--c-brand)` + `var(--c-brand-contrast)`。

不要让 `--c-brand` 直接当文字色——`#B84E27` 对纸面只有 4.73:1，勉强过 AA，但作为大面积小字会显脏；反过来用 `--c-brand-ink` 填充会偏暗，失去印章的鲜艳感。

全部语义色对必须达 WCAG AA（4.5:1）。当前实测值见 [验收记录](./evidence/design-2026-11-11/report.json)。

### 排版

- `--font-sans`：霞鹜文楷（`'LXGW WenKai'`），站点自托管于 `apps/web/public/fonts/lxgw-wenkai/`，按 unicode-range 分片，仅下载页面实际用到的切片；其后依次回退系统中文黑体栈（`-apple-system` / `PingFang SC` / `Microsoft YaHei` / `Noto Sans CJK SC`）。全局生效：`html`、Ionic `--ion-font-family` 均指向该令牌。
- `--font-display`：与 `--font-sans` 同源，标题、计数、序号与字标统一使用霞鹜文楷。
- 字号阶：`--fs-2xs 11 / xs 12 / sm 13 / base 15 / md 17 / lg 20 / xl 24 / 2xl 30 / 3xl 38`。
- 行高：CJK 正文不低于 1.6，标题 1.25。
- 字重对比：标题 600，正文 400，弱化文字 400 + 降色（不靠降字号制造层次）。

### 间距 / 圆角 / 阴影 / 动效

- 间距阶：`--sp-1 4` … `--sp-8 48`（4 的倍数）。
- 圆角：`--r-sm 4`（标签）、`--r-md 8`（输入框、缩略图）、`--r-lg 12`（面板）、`--r-pill 999`（芯片）。
- 阴影用暖墨色低透明度，不用纯黑：`--shadow-1/2/3`。
- 动效：`--dur-fast 120ms` / `--dur-base 200ms` / `--dur-slow 320ms`；缓动 `--ease-out`（状态澄清）与 `--ease-spring`（选中反馈）。

## 组件规范

| 组件                      | 规范                                                                                                                                    |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 食材芯片 `IngredientChip` | 未选：纸白底 + 墨线边框 + emoji 装在圆形 `--c-emoji-wash` 容器；已选：陶土橙实底 + 白勾（印章感）。保持 `aria-pressed` 与 44px 触控高度 |
| 结果行 `RecipeResultRow`  | 圆形 emoji 纸章容器 + 菜名（--fs-md）+ 食材摘要（--fs-sm，--c-ink-2）；缺食材用 `--c-warn`，不再用橙色                                  |
| 按钮 `btn` / 标签 `tag`   | UnoCSS shortcut 改为令牌驱动（`--c-brand` / `--c-rule`），去掉硬编码 `bg-blue-600`                                                      |
| 输入框                    | `--c-paper-sunk` 底 + 墨线边框，聚焦时陶土橙焦点环（2px，保留可见焦点）                                                                 |
| 骨架屏 `ResultsSkeleton`  | 暖灰脉冲，形状对齐真实结果行，避免加载时布局跳动                                                                                        |
| 侧栏导航                  | 选中态为墨线强调底 + `--c-brand-ink` 文字与图标，不再整块蓝底；平板态只显示图标                                                         |
| 列表图标 `CookListIcon`   | 用暖色系色组（陶土橙、赭黄、墨绿、黛紫、石墨），不再用 iOS 系统蓝/紫/亮绿                                                               |

## 品牌资产

- **唯一设计源**：仓库根目录 `logo.png`（手账插画）。
- **生成**：`node scripts/generate-brand-icons.mjs` 派生 Web 品牌图、favicon、apple-touch-icon、PWA 图标、关于页与文档站的品牌 SVG、iOS AppIcon 兜底位图与 Icon Composer 分层图标。换 logo 只需替换源文件后重跑，不要手工改派生图。
- **浅色底**：图标统一用暖纸色 `#FBF7F0` 作不透明底；位图输出为不带 alpha 的 RGB（iOS 不接受透明），只有 Icon Composer 的图层保留透明并抠掉白色外边。
- **原生端**：iOS 的 `AccentColor`（浅 `#B84E27` / 暗 `#E08A5F`）与 `LaunchBackground` 跟随同一组令牌；Android 的映射见 [Android 分阶段计划](./android-roadmap.md)。

## 内容状态矩阵

每个状态都要有明确触发条件、可见反馈与安全的下一步：

| 状态 | 触发                 | 可见反馈                       | 安全的下一步               |
| ---- | -------------------- | ------------------------------ | -------------------------- |
| 加载 | 首次加载菜谱 JSON    | 骨架屏，结构与真实结果行一致   | 等待（无取消，数据在本地） |
| 空   | 未选任何食材且无结果 | 说明「还没选食材」并给示例入口 | 「试试番茄＋鸡蛋」一键示例 |
| 错误 | 数据解析失败         | 具体失败原因                   | 重试 / 反馈入口            |
| 部分 | 部分菜谱缺视频或做法 | 正常展示可得的字段             | 进入详情页看已有内容       |
| 成功 | 收藏、保存、提交反馈 | 轻提示确认                     | 继续浏览或撤销（可撤销时） |
| 权限 | 需要登录才能同步     | 说明访问边界                   | 登录入口 + 安全返回        |

## 验收

1. 在 390×844、834×1024、1440×900 三个视口分别截图并人工检查：键盘可达、焦点可见、标签完整、对比度、窄屏长文本不溢出、触控目标 ≥44px、`prefers-reduced-motion` 下无位移动画。
2. 逐个走查上表六种内容状态，截图留在仓库内。
3. 写 evidence 记录并跑随 skill 附带的检查器：

```bash
# skill 脚本是 CommonJS，而本仓库是 type: module，需用 .cjs 副本运行
cp .claude/skills/frontend-design-direction/scripts/check-evidence.js /tmp/check-evidence.cjs
node /tmp/check-evidence.cjs docs/dev/evidence/<日期>/report.json
```

记录包含 `contract`、`targetViewports`、`accessibility`、`responsive`、`contentStates`（六态齐备）、`renderedEvidence`（每个目标视口一条，artifact 为报告目录内的非软链文件）。

## 改动检查清单

- 颜色只走令牌，组件内不出现十六进制色值。
- 新断点只用 768px / 1200px；不新增 1024 / 1280 的一次性值。
- 触碰文字的主色用 `--c-brand-ink`，触碰填充的主色用 `--c-brand`。
- 明暗两套都要看：暗色不是浅色的反相，纸面与墨线仍要有层次差。
- 改了令牌或组件后重跑上面三步验收，并更新 evidence 记录。
